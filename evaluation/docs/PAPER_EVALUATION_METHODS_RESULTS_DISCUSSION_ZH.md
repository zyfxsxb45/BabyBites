# BabyBites 系统测评方法、结果与讨论

## 摘要

本研究围绕婴幼儿辅食决策支持系统 BabyBites，构建了涵盖候选食物选择、安全规则触发、反事实一致性、宝宝画像抽取、周计划生成及检索增强开放回答六类任务的多层次评测框架。评测以使用相同 DeepSeek 模型的纯大语言模型作为基线，并在开放式生成任务中引入 Qwen 第三方盲评，其中周计划任务采用 Qwen3.7-plus 双向盲评。对于确定性分类任务，采用 Accuracy、Macro-F1、风险召回率和严重风险漏报率等指标；对于开放式生成任务，采用多维度第三方评分、A/B 盲评和安全错误审查；统计推断采用配对 Wilcoxon 符号秩检验、精确 McNemar 检验、Bootstrap 置信区间及 Holm 多重比较校正。

结果显示，BabyBites 在候选食物选择、严重风险识别、低于 6 月龄阻断及反事实一致性方面显著优于纯 DeepSeek 基线。候选食物选择逐案例 Accuracy 分别为 0.852 和 0.698，差值为 0.154，Holm 校正后 `p<0.001`；严重风险召回率分别为 0.993 和 0.907，严重风险漏报率分别为 0.007 和 0.093。BabyBites 的反事实完整配对准确率达到 1.000，显著高于基线的 0.267。相对而言，BabyBites 在画像抽取任务中明显落后于基线；在周计划生成和 RAG 开放回答中，两系统综合评分未观察到统计学显著差异。上述结果表明，显式规则、知识库与确定性安全边界可显著增强系统在结构化安全决策中的稳定性，但尚不能自然转化为开放式文本生成质量和画像抽取能力。

## 1. 研究目的

本测评旨在回答以下问题：

1. BabyBites 是否能够比不接入外部知识库和规则引擎的纯 DeepSeek 基线更准确地完成辅食候选分类？
2. BabyBites 是否能够降低已知过敏、月龄不足等严重风险的漏报概率？
3. 当宝宝画像中的关键风险变量发生单一变化时，BabyBites 是否能够产生方向正确且一致的决策变化？
4. BabyBites 在宝宝画像抽取、七天周计划和 RAG 开放回答等生成式任务中是否具备优势？
5. 当前观察到的性能差异是否具有统计学证据支持，以及结果受到哪些数据与评测设计限制？

## 2. 测评系统与对照设置

### 2.1 BabyBites

BabyBites 是由宝宝画像、知识库、规则引擎、RAG 检索、计划生成和对话模块组成的复合系统。对于候选食物选择和安全边界判断，系统主要依赖结构化宝宝画像、候选食物属性和确定性规则；对于画像抽取、开放问答及部分计划生成流程，系统调用 DeepSeek 大语言模型。系统能够使用已知过敏原、矫正月龄、候选食物最低推荐月龄、配料信息、质地、近期不良反应和家长偏好等信息。

### 2.2 纯 DeepSeek 基线

基线系统使用与 BabyBites 主要大模型配置一致的 `deepseek-v4-pro`，但不接入 BabyBites 的知识库、知识图谱和规则引擎。基线在每条样本中获得完整宝宝画像、自然语言任务请求和候选食物信息，并直接生成分类或自然语言回答。因此，本实验比较的是“复合决策系统”与“同模型纯 LLM”之间的整体性能差异，而不是单独衡量某一个规则模块的增益。

### 2.3 第三方评测模型

周计划生成和 RAG 开放回答采用阿里云百炼 Qwen 模型进行第三方盲评。当前定稿的周计划结果使用 `qwen3.7-plus`。评测模型仅获得宝宝画像、统一任务请求、候选食物及匿名输出 A/B，不获得系统身份。

周计划任务对每个样本进行两次评测：第一次随机分配 A/B，第二次完全反转 A/B 顺序。只有两次评测均选择同一实际系统时，才将该系统计为获胜；顺序反转后结论不一致的样本记为平局。两次评分的均值用于连续评分分析。该设计用于降低位置偏倚和标签顺序偏倚。

### 2.4 三方输入协议与公平性控制

对于候选选择、安全触发、反事实一致性和周计划任务，BabyBites 与纯 DeepSeek 均基于同一条评测案例运行，包括相同的完整宝宝画像、任务请求和候选食物集合。两者的主要区别在于：BabyBites 通过评测适配器将案例转换为产品原生结构化输入，并可调用内部规则、知识库和工作流；纯 DeepSeek 直接接收完整结构化画像及候选信息，但不获得 BabyBites 内部规则目录和 canonical rule ID。

对于画像抽取任务，双方均接收同一自然语言家长描述，并分别输出结构化画像。对于 RAG 开放回答，BabyBites 可以使用检索结果，基线不接入外部知识库；该设计用于衡量检索增强系统相对于纯模型的整体增益。

第三方 Qwen 获得的输入包括宝宝画像、统一任务请求、候选食物、匿名输出 A 和匿名输出 B。Qwen 不获得 BabyBites 内部检索文档、规则触发过程或系统名称，避免根据系统实现而非最终输出评分。

周计划双方使用统一的七天计划请求，且评测端不再对 BabyBites 施加额外的短输出要求。基线在周计划和 RAG 任务中的最大输出长度为 4,096 tokens，候选选择为 3,600 tokens，其他任务为 1,800 tokens。BabyBites 内部不同代理仍可能使用各自的调用配置，因此当前协议实现了任务内容和外部评测输入公平，但并非严格的组件级 token 消耗等量实验。

## 3. 评测数据

### 3.1 数据生成原则

初始评测集共生成 1,000 条样本，包括候选食物选择 250 条、安全规则触发 200 条、周计划生成 200 条、画像抽取 150 条、反事实一致性 100 条和 RAG 开放回答 100 条。

宝宝画像并非直接复制真实数据库中的单个受试者记录，而是利用 NHANES 1999、WIC ITFPS-2 和 IFPS2 提供的字段结构、可读取经验分布、合法范围与规则组合生成。生成流程保留数据来源追踪字段，但不保留可识别个人信息。食物属性和营养值主要用于构造评测条件及风险标签，不应视为临床级精确营养数据库。

### 3.3 宝宝画像分布

各任务画像覆盖 4 至 36 月龄。候选食物选择任务平均月龄为 12.99 月，中位月龄为 11 月；周计划任务平均月龄为 11.41 月；安全规则触发任务平均月龄相对较高，为 17.15 月。候选食物选择样本中，早产比例为 13.0%，具有已知过敏原的比例为 68.8%，具有疑似过敏史的比例为 81.8%。

各任务画像分布并非完全一致。例如，反事实任务主要围绕单一变量变化构造，其疑似过敏史字段分布与其他任务不同；安全规则和 RAG 任务中已知过敏原比例较高。这种任务定向采样有利于覆盖风险场景，但意味着不同任务之间的绝对性能不宜直接横向比较。

### 3.4 标准答案与风险标签构造

结构化分类任务的标准答案由统一确定性规则生成，而非由 GPT、Qwen 或 BabyBites 在线输出直接决定。评测器根据宝宝实际或矫正月龄、已知过敏原、候选食物最低推荐月龄、配料信息、窒息风险和禁止成分等字段，生成 `safe/caution/avoid` 标签及通用风险类型。

规则优先级为：已知过敏冲突、低于 6 月龄、低于食物最低推荐月龄和明确禁止成分优先判为 `avoid`；可通过加工管理的窒息风险、潜在过敏原、新食物、糖盐高钠、质地需调整及配料信息不足判为 `caution`；仅在不存在上述信号时判为 `safe`。配料未知样本不得判为 `safe`。

该方法保证 BabyBites 和基线按同一标准评分，但标准答案仍是预定义政策标签，而非经过儿科专家逐例确认的临床金标准。因此，本文中的 Accuracy 和 F1 应解释为“相对于当前评测协议的正确率”，而非临床诊断正确率。

## 4. 任务与评价指标

### 4.1 候选食物选择

候选食物选择要求系统将每个候选食物分类为：

- `safe`：不存在硬风险，配料信息充分，月龄和质地适合；
- `caution`：可以在满足加工、观察或信息补充条件后使用；
- `avoid`：当前不应选择，例如已知过敏冲突、低于 6 月龄、低于食物最低推荐月龄或存在明确禁止成分。

“avoid”表示当前条件下不应选择，并不等于永久禁止该食材。可通过切碎、压泥等方式解决的窒息风险归入 `caution`；配料未知不得判为 `safe`。

主要指标包括逐案例 Accuracy、食物级 Accuracy、Macro-F1，以及以下安全专项指标：

- `hard_risk_recall`：严重风险候选被正确判为 `avoid` 的比例；
- `hard_risk_false_negative_rate`：严重风险未被判为 `avoid` 的比例，越低越好；
- `over_caution_rate`：标准答案为 `safe` 的食物被判为非 `safe` 的比例，越低越好；
- `allergy_conflict_recall`：已知过敏冲突召回率；
- `under_6_block_rate`：低于 6 月龄时阻断辅食的比例；
- `choking_risk_recall`：窒息风险被识别为 `caution` 或 `avoid` 的比例；
- `unknown_ingredient_safe_rate`：未知配料被误判为 `safe` 的比例，目标为 0。

### 4.2 安全规则触发

安全规则触发任务要求系统对单个食物作出 `safe/caution/avoid` 判断，并识别通用 `risk_types`。为避免 BabyBites 内部规则 ID 对基线产生不公平优势，双方均先输出与系统实现无关的通用风险类型，再由同一确定性映射函数转换为 canonical rule ID。

主要指标为决策正确率；辅助指标包括决策 Macro-F1、风险类型 F1 和规则 ID Micro-F1。

### 4.3 反事实一致性

每组反事实样本包含两个独立输入，仅改变一个关键变量，例如将“无牛奶过敏”改为“已知牛奶过敏”，并观察系统决策是否按预期变化。两个画像分别调用系统，不会在同一输入中同时呈现。

主要指标为完整配对准确率：只有一对中的两个案例均判断正确，才将该对计为正确。

### 4.4 画像抽取

画像抽取任务要求系统从自然语言家长描述中恢复结构化字段，包括实际月龄、矫正月龄、是否早产、胎龄、过敏原、已尝试食物和备注目标等。主要指标为字段准确率，即逐字段完全匹配后的平均值。

### 4.5 周计划生成

双方使用统一请求生成七天辅食计划，每天安排 1 至 2 种食物，只允许从给定候选食物中选择。普通可用候选优先；仅当普通可用候选仅剩 0 或 1 种时，才允许纳入可通过加工或观察管理的 `caution` 食物，且必须给出对应加工方法或警告。

Qwen 第三方评测维度包括：

- 月龄适配；
- 过敏安全；
- 严重风险安全；
- 营养均衡；
- 长期计划质量；
- 细节与可执行性；
- 候选食物遵循度；
- 综合评分。

同时报告完整七天计划率和第三方标记安全错误比例。

### 4.6 RAG 开放回答

RAG 开放回答用于比较 BabyBites 检索增强回答与纯 DeepSeek 回答。第三方评测维度包括月龄适配、过敏安全、严重风险安全、营养均衡、证据依据、完整性、细节可执行性、家长友好度和综合评分。

## 5. 统计分析

所有比较均为配对设计，因为 BabyBites 与基线在相同样本上接受评测。

1. 对逐案例 Accuracy、Macro-F1 和第三方连续评分，采用双侧 Wilcoxon 符号秩检验。
2. 对正确/错误、安全错误有无、完整七天计划与安全专项二元指标，采用精确 McNemar 检验。
3. 对主要指标的配对均值差异，通过 20,000 次 Bootstrap 重采样计算 95% 置信区间。
4. 主要任务指标在任务集合内使用 Holm 方法进行多重比较校正。
5. Figure 2 展示的 7 项安全指标单独进行 Holm 校正。
6. 显著性阈值设为校正后 `p<0.05`。

McNemar 检验仅利用双方结果不一致的配对。例如，当双方对所有过敏冲突均判断正确时，虽然召回率均为 1.000，但不存在不一致配对，因此 `p=1.000`。这并不表示指标无价值，而是表示当前样本无法证明双方存在差异。

### 6.2 候选食物选择

在 77 个案例和 478 个候选食物上，BabyBites 的食物级 Accuracy 为 0.856，纯 DeepSeek 为 0.701；Macro-F1 分别为 0.853 和 0.705。逐案例平均 Accuracy 差值为 0.154，Holm 校正后仍具有显著性。

分类别结果显示：

| 类别 | 指标 | BabyBites | 纯 DeepSeek |
|---|---|---:|---:|
| safe | Precision | 0.680 | 0.603 |
| safe | Recall | 1.000 | 0.894 |
| safe | F1 | 0.810 | 0.720 |
| caution | Precision | 0.995 | 0.930 |
| caution | Recall | 0.731 | 0.522 |
| caution | F1 | 0.843 | 0.668 |
| avoid | Precision | 0.832 | 0.605 |
| avoid | Recall | 0.993 | 0.907 |
| avoid | F1 | 0.906 | 0.726 |

BabyBites 的优势并非仅来自更保守地输出 `avoid`。其安全食物召回率达到 1.000，且安全食物过度警告率为 0；纯 DeepSeek 的过度警告率为 0.106。这说明在当前评测规则下，BabyBites 同时减少了严重风险漏报和对安全食物的过度警告。

### 6.4 安全规则触发

BabyBites 与纯 DeepSeek 的安全规则触发决策正确率分别为 0.650 和 0.600，差异不显著。BabyBites 决策 Macro-F1 为 0.636，基线为 0.590。

但 BabyBites 的 Risk-type F1 仅为 0.100，明显低于基线的 0.602。该结果表明，BabyBites 虽然能够作出相对合理的最终 `safe/caution/avoid` 决策，但当前评测适配层未能稳定输出完整、标准化的 provider-neutral `risk_types`。因此，该结果更可能反映输出协议和适配器缺口，而不仅是底层安全判断能力不足。后续应将 BabyBites 内部触发原因稳定映射为通用风险类型，并避免仅依赖自然语言理由或内部规则 ID。

### 6.5 反事实一致性

在 15 个完整反事实配对中，BabyBites 的完整配对准确率为 1.000，纯 DeepSeek 为 0.267，配对差值为 0.733，Holm 校正后 `p=0.004`。11 对样本仅 BabyBites 完整正确，没有出现仅基线完整正确的配对。

该结果说明，当关键风险变量发生单一变化时，显式规则路径能够稳定地使决策随变量变化。纯 LLM 虽可在部分单案例上作出合理判断，但对“仅改变一个变量后必须同步改变决策”的约束执行不稳定。

需要注意，反事实样本来自规则化构造，其变化变量与 BabyBites 的规则体系高度相关。因此，该任务证明的是系统对已定义规则变量的稳定响应能力，而不能直接推广为对所有真实世界反事实情境的因果推理能力。

### 6.6 画像抽取

BabyBites 的字段准确率为 0.362，低于纯 DeepSeek 的 0.505，差值为 -0.143，Holm 校正后 `p=0.001`。这是 BabyBites 当前最明确的性能短板。

该结果说明，结构化输入能力并不等同于自然语言画像抽取能力。当前画像抽取评测首先提供家长自然语言描述，再比较系统恢复出的标准字段；BabyBites 的规则或前端结构化路径无法自动保证其自然语言抽取路径准确。可能误差来源包括字段命名不一致、中英文食物实体未完全规范化、缺失字段默认值处理差异，以及备注字段与显式字段之间的信息融合不足。

### 6.7 周计划生成

周计划任务共纳入 68 条样本。Qwen3.7-plus 双向盲评中，两次顺序评测结论一致的样本为 52 条，一致率为 76.5%；最终 BabyBites 获胜 29 条，基线获胜 23 条，16 条因方向不一致记为平局。

| 维度 | BabyBites | 纯 DeepSeek |
|---|---:|---:|
| 月龄适配 | 4.662 | 4.640 |
| 过敏安全 | 4.507 | 4.765 |
| 严重风险安全 | 4.640 | 4.831 |
| 营养均衡 | 3.904 | 4.118 |
| 长期计划质量 | 3.890 | 3.971 |

| 候选食物遵循度 | 4.669 | 4.735 |

两系统综合评分几乎相同，配对差值为 -0.007，未达到统计学显著性。BabyBites 在细节与可执行性方面明显更高，但在过敏安全、严重风险安全、营养均衡和长期计划质量方面低于基线。

BabyBites 的完整七天计划率为 0.868，基线为 0.897，差异不显著。第三方评测未标记安全错误的比例分别为 0.926 和 0.985，差异亦不显著，但 BabyBites 被标记安全错误的案例数更多。该现象说明当前计划生成流程虽然增强了操作说明，但仍需强化候选筛选后的二次安全校验和跨七天营养结构优化。

## 7. 讨论

### 7.1 显式规则显著改善高风险决策稳定性

BabyBites 在候选食物选择、严重风险召回、低于 6 月龄阻断和反事实一致性方面的优势具有一致方向。该结果支持将高风险辅食约束从大语言模型的隐式知识中分离出来，并由确定性规则执行。纯 DeepSeek 能够识别大多数常见风险，但其错误更集中于边界条件、风险等级映射和跨样本一致性。

尤其值得注意的是，BabyBites 并未因规则约束而增加安全食物的过度警告。相反，其过度警告率低于基线。这说明合理设计的 `safe/caution/avoid` 优先级可以同时改善敏感性和特异性，而非必然导致过度保守。

### 7.2 规则优势未自动转化为开放式生成优势

周计划和 RAG 开放回答的综合评分未显示 BabyBites 的显著优势。可能原因包括：

1. 规则和知识检索能够约束“不能做什么”，但高质量开放回答还需要内容组织、营养多样性、长期节奏设计和自然语言表达能力。
2. 纯 DeepSeek 本身具备较强的常识与语言生成能力，在小样本开放任务中已达到较高评分，形成明显天花板效应。
3. BabyBites 的规则输出和候选筛选结果若未以紧凑、清晰的形式传递给计划生成模型，可能增加上下文复杂度，却未带来等比例收益。
4. RAG 文档块的检索命中不等于回答中的证据使用。当前 BabyBites 的证据依据评分低于基线，提示检索结果可能未被充分整合或引用。

### 7.3 画像抽取是当前系统链路中的关键瓶颈

BabyBites 在画像抽取任务中的显著劣势具有实际影响。规则引擎的判断质量依赖结构化画像的正确性；若自然语言输入被错误抽取，后续确定性规则可能稳定地执行错误画像。因此，系统安全性不能只关注规则引擎，还必须对画像抽取建立字段级校验、实体规范化和用户确认机制。

推荐优先改进：

1. 建立中英文食物和过敏原统一实体表；
2. 区分“已知过敏”“近期不良反应”“家长主动避免”和“未尝试食物”；
3. 对月龄、矫正月龄、早产状态和过敏原执行显式一致性检查；
4. 对低置信度字段要求用户确认，而不是自动填充默认值；
5. 分别报告各字段 Precision、Recall 和 F1，而非仅报告整体字段准确率。

### 7.4 安全规则触发任务暴露输出协议问题

BabyBites 的最终决策性能略高于基线，但 Risk-type F1 显著较低，说明“做出正确决定”与“以标准协议解释决定”是两个不同问题。若系统不能稳定输出通用风险类型，将降低可审计性、跨版本比较能力和规则 ID 映射质量。

后续应将通用 `risk_types` 作为后端正式响应字段，而不是由评测适配器根据自然语言理由反推。内部规则 ID、通用风险类型和用户可读解释应形成三层明确映射。

### 7.5 第三方模型评审仍存在不稳定性

周计划双向盲评中有 16/68 的样本在反转 A/B 后改变结论，表明第三方模型评审存在顺序敏感性。双向盲评并将不一致样本记为平局能够减少偏倚，但不能完全替代人工专家评审。

此外，Qwen 评分属于模型偏好评价，并非临床正确性结论。尤其是安全错误判断可能受到评审提示词、输出长度和表述方式影响。因此，开放任务应同时报告确定性安全审查、第三方盲评和人工复核结果。

## 8. 局限性

1. **数据并非真实临床队列。** 当前样本基于真实数据库分布、字段结构和规则约束进行合成，不能直接代表真实家庭使用场景中的疾病谱与行为分布。
2. **候选食物营养值为评测构造值。** 其用途是构造规则与比较条件，不应作为精确营养数据库使用。
3. **任务样本量不均衡。** RAG 仅 10 条、画像抽取仅 15 条、安全规则触发仅 20 条，统计功效有限。
4. **候选选择采用中期扩充快照。** 当前使用 77 条案例，其中新增 52 条来自尚在运行时保存的完整结果快照；最终全量结果可能略有变化。
5. **任务定向采样造成画像分布差异。** 各任务风险比例和月龄构成不同，任务间绝对指标不可直接比较。
6. **标准答案依赖预定义规则。** 结果证明系统与当前 canonical 规则的一致性，不等同于临床指南的最终正确性。高钠阈值、最低推荐月龄和风险等级仍需由儿科或营养专家确认。
7. **开放任务第三方评审并非人工专家评审。** Qwen 可能存在位置偏倚、提示词敏感性和模型自身知识偏差。
8. **系统与基线并非组件级消融。** BabyBites 使用规则、知识库和工作流，基线为纯 LLM；结果反映整体系统差异，不能单独归因于某一个模块。
9. **画像抽取标准存在实体规范化限制。** 中英文实体、同义词和部分字段默认值仍可能影响完全匹配指标。
10. **RAG 样本量和证据评价不足。** 当前尚不足以稳定证明检索增强对回答质量的净收益。

## 9. 结论

本研究建立了一个覆盖结构化安全判断、反事实一致性、画像抽取和开放式生成的 BabyBites 多任务评测框架。结果表明，BabyBites 的显式规则与安全边界能够显著提高候选食物选择准确率，降低严重风险漏报，并增强关键变量变化下的决策一致性。其优势主要集中于规则约束明确、标准答案可确定的任务。

与此同时，BabyBites 在画像抽取任务中显著落后于纯 DeepSeek；在周计划和 RAG 开放回答任务中尚未表现出显著综合优势。未来系统优化重点不应仅继续增加规则，而应加强画像抽取可靠性、风险类型标准化输出、计划生成后的确定性安全复核、RAG 证据整合及真实用户场景验证。

总体而言，当前证据支持将 BabyBites 定位为“由规则和知识增强的辅食决策支持系统”，而非能够替代专业人员的临床建议系统。其最明确的价值是提升高风险边界判断的一致性和可审计性；其主要挑战是将这种结构化安全优势进一步传递到自然语言理解和开放式计划生成环节。
