# BabyBites 前端开发分析

## 一、技术栈

| 层 | 技术 |
|---|---|
| 框架 | React 19 |
| 构建 | Vite 8 |
| 图表 | Recharts（雷达图） |
| HTTP | 原生 `fetch`（无 axios 依赖） |
| 样式 | 纯 CSS（全局样式表，CSS 变量管理品牌色） |
| 路由 | 无（单页条件渲染，`activeTab` 状态驱动） |
| 状态管理 | 无外部库（纯 React `useState` / `useEffect` / `useRef`） |
| 持久化 | `localStorage`（计划进度、历史归档、LLM 设置） |

## 四、状态管理

全部使用 React `useState`，无外部状态管理库。

### 全局状态（App 组件，通过 props 下传）

| 状态 | 类型 | 说明 |
|---|---|---|
| `profile` | object (14 字段) | 宝宝画像，所有侧边栏字段的统一载体 |
| `assessment` | object/null | `/api/assess` 返回的安全评估结果 |
| `plan` | object/null | `/api/plan` 返回的周度计划 |
| `activeTab` | string | 当前激活的 Tab（默认 `"plan"`） |
| `useLLM` | boolean | LLM 排菜模式开关 |
| `error` | string/null | 全局错误提示（可关闭卡片） |
| `loading` | boolean | 全局加载状态 |
| `settingsOpen` | boolean | 设置面板开关 |

### 局部状态（子组件内部）

| 组件 | 局部状态 |
|---|---|
| WeeklyPlan | `expandedDay`, `planHistory`, `showHistory`, `planStartedAt` |
| DailyFeedback | `foodName`, `reaction`, `severity`, `notes`, `feedbackHistory`, `submitting`, `message` |
| LabelParser | `text`, `age`, `result`, `loading` |
| SettingsPanel | `apiKey`, `baseUrl`, `model`, `loading`, `msg` |
| BossBabyChat | `open`, `msgs`, `input`, `loading`, `tooltip` |

## 五、数据流

```
用户操作                           API 调用                     状态变化
─────────                         ────────                     ────────
填写侧边栏 → 点击「开始评估」 → POST /api/assess          → setAssessment
  └─ can_start=true            → 自动 POST /api/plan       → setPlan
  └─ can_start=false           → 跳转 📊 阶段判断 Tab

点击「刷新计划」                → POST /api/plan           → setPlan
勾选 🤖 LLM 排菜               → 同上 (携带 use_llm=true)

提交喂养反馈                   → POST /api/feedback       → 自动 POST /api/plan
                                                              → setPlan (排除问题食材)

保存 LLM 设置                  → POST /api/settings/llm   → 后端热重载所有 Agent

发送聊天消息                   → POST /api/chat            → 追加对话历史
                                 (+ current_profile)         个性化回答

配料表解析                     → POST /api/parse-label     → setResult
```

### 关键流程

1. **评估→计划自动串联**：`doAssess()` 成功后若 `can_start=true`，自动调用 `doPlan()`
2. **反馈闭环**：提交反馈 → 调 `onFeedbackSubmit()` → `doPlan()` → 计划自动排除问题食材
3. **LLM 热重载**：保存设置 → `_reload_llm()` 更新全局 `llm` + safety/plan/label/chat 四个 Agent 的实例
4. **备注过敏提取**：流程中同时跑 LLM 语义理解 + 关键词 fallback，确保覆盖

## 六、核心特性

| 特性 | 实现方式 |
|---|---|
| **Tab 切换** | `activeTab` 状态 + 条件渲染 + `key={activeTab}` 强制 remount + CSS fade-in |
| **巴士排菜表** | 纯 CSS：渐变车身 / 不对称圆角 / `absolute` 定位车轮 / `::before` 尾灯 `::after` 前照灯 |
| **今日高亮** | 匹配 `date` 字段 vs `today.toISOString()`，绿色边框 + 绿色外发光 + "今天"徽章 |
| **日期对齐** | 后端 `_start_date()` 从 `date.today()` 起算；前端 `day` 名称对应 `plan_date.weekday()` |
| **历史归档** | localStorage + `useEffect` 定时器 30 分钟跨天检查 + `useRef` 避免闭包过期 |
| **食材详情展开** | `expandedDay` 状态控制，点击切换；`food_details` 来自后端合作者新增 |
| **营养雷达图** | Recharts `<RadarChart>` 硬编码 5 维模拟数据，品牌橙色系 |
| **LLM 模式** | 复选框控制 `useLLM`；计划返回 `mode: "llm"/"rule"/"rule_fallback"` 在前端展示 |
| **自定义过敏原** | 输入框回车添加；虚线边框 chip（`.chip.custom`）；后端直接食材名匹配 |
| **备注过敏解析** | 后端 SafetyBoundaryAgent：LLM 语义理解 + 关键词 fallback；前端橙色提示卡片 |
| **反馈闭环** | 每日食材快速选择 → 反应/严重度 → 提交 → 自动刷新计划 → 排除问题食材 |
| **LLM 设置面板** | 模态弹窗；4 个预设一键切换；后端 JSON 持久化 + Agent 热重载 |
| **Logo 品牌** | 侧边栏/标题/聊天窗三处使用 `logo.png`；Vite `public/` 静态托管 |
| **CSS 设计系统** | `:root` CSS 变量统一品牌色 (`--orange`, `--text`, `--card` 等) |

## 七、优点

1. **零外部状态库依赖** — 纯 React hooks 驱动，无 Redux/MobX/Zustand，学习成本低，打包体积小
2. **API 层简洁** — `api.js` 仅 57 行，`fetch` 薄封装 + 结构化方法，一目了然
3. **组件职责清晰** — 每个组件对应一个明确的业务模块（评估/标签/排菜/配料/反馈/设置/聊天）
4. **数据流单向** — 状态从 App 向下流动，回调函数向上传递，符合 React 设计哲学
5. **评估→计划自动串联** — 用户体验流畅，一次点击完成评估+排菜，无需额外操作
6. **localStorage 持久化** — 计划进度/历史记录跨会话保留，不依赖后端数据库
7. **CSS 创意实现** — 巴士造型完全用 CSS（渐变/伪元素/绝对定位），不引入额外图片
8. **设计系统一致** — CSS 变量统一品牌色，全局复用，视觉统一
9. **LLM 热重载** — 设置即时生效，无需重启，不中断用户操作
10. **渐进增强** — LLM 不可用时自动降级到规则模式，不影响核心功能

## 八、缺点与改进方向

| 问题 | 严重度 | 改进建议 |
|---|---|---|
| **单文件过大** — App.jsx 1166 行含 10 个组件 | 🔴 高 | 拆分为 `components/` 目录，每个组件独立文件 |
| **无路由** — URL 不变，无法分享/收藏特定视图 | 🟡 中 | 引入 React Router，Tab 映射到 URL hash |
| **无类型检查** — props 传递无保障 | 🟡 中 | 迁移 TypeScript 或加 PropTypes |
| **CSS 全局污染** — 所有样式在单个 App.css 中 | 🟡 中 | CSS Modules 或 Tailwind CSS |
| **无状态管理方案** — profile 14 字段多层 props 下传 | 🟡 中 | Context API 或 Zustand |
| **无错误边界** — API 失败部分覆盖不全 | 🟡 中 | ErrorBoundary + 统一 toast 组件 |
| **无加载骨架** — loading 只显示文字 | 🟢 低 | Skeleton 组件 |
| **无前端测试** — 0 测试覆盖 | 🟡 中 | Vitest + React Testing Library |
| **Chat 嵌入主文件** — BossBabyChat 含复杂 CSS 动画 | 🟢 低 | 独立文件 |
| **API Base URL 硬编码** — `http://localhost:8000` | 🟢 低 | `VITE_API_BASE` 环境变量 |
| **无障碍缺失** — Chip 用 `<span>` 非 `<button>` | 🟢 低 | 语义化 HTML + ARIA |
| **planHistory 闭包 hack** — useRef 手动管理 | 🟢 低 | useReducer 或 local-storage hook 库 |

## 九、与后端关系

```
前端 (React + Vite)                    后端 (FastAPI + Uvicorn)
─────────────────                      ─────────────────────────
api.assess(profile)          ──POST──→  /api/assess
  ←── { can_start, stage,              SafetyBoundaryAgent 处理
        food_tags, notes_avoid_foods }  RuleEngine 规则评估

api.plan(profile)            ──POST──→  /api/plan
  ←── { plan[], new_foods,             PlanGenerationAgent 处理
        nutrition_notes,               RuleEngine 安全过滤
        food_details, mode }           FeedbackStore 反馈调整

api.chat(msg, hist, profile) ──POST──→  /api/chat
  ←── { answer, sources }              ChatAgent 处理

api.feedback.submit(data)    ──POST──→  /api/feedback
  ←── { record, summary }              FeedbackStore 持久化

api.parseLabel(text, age)    ──POST──→  /api/parse-label
  ←── { parsed[], risk_summary }       LabelParsingAgent 处理

api.settings.saveLLM(data)   ──POST──→  /api/settings/llm
  ←── { status, model }                热重载全局 llm + 所有 Agent
```

## 十、典型用户操作流程

```
1. 打开页面 → 📅 周度辅食计划 Tab（默认激活）
2. 左侧边栏填写信息 → 点击「🔍 开始评估」
3. 自动跳转 📊 阶段判断，显示月龄/就绪信号/食材标签
4. can_start=true → 自动生成计划 → 跳转 📅 周度计划
5. 查看巴士排菜表 → 点击窗户看食材详情（做法/营养/注意）
6. (可选) 勾选 🤖 LLM 智能排菜 → 刷新计划 → 获得个性化推荐
7. 每天执行后 → 在 📝 每日反馈标记反应 → 计划自动调整
8. 第二天打开 → 昨天自动归档到 📜 排菜历史
9. 点击 💬 Boss Baby → 咨询辅食问题（个性化回答）
10. (可选) ⚙️ 设置面板 → 切换自己的 API Key 和模型
```
